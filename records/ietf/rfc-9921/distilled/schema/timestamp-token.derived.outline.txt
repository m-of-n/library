rfc-9921 Appendix A -- the structure of the printed TimeStampToken
=================================================================
DERIVED -- not verbatim. RFC 9921 prints no ASN.1 module and its own value
dumps are truncated with "[...]" (source lines 592 and 835). The outline below
was produced BY DECODING the 5453 octets of Appendix A.1's hex with a DER
parser written for this pass -- no ASN.1, CMS, X.509 or cryptography library
was used -- and every offset and length is the decoder's output, not a reading
of the prose. The filename carries `.derived.` as docs/extraction.md requires.

The grammar these octets obey belongs to RFC 5652 (CMS, STD 70) and RFC 3161,
NEITHER OF WHICH THIS LIBRARY HOLDS. So the names in the left column are this
extraction's identification of the structures, checked against the OIDs the
bytes carry, and not quotations of a specification we can cite from here.

Appendix A.2's token has the same shape, the same certificate chain and the
same lengths; it differs in TSTInfo.messageImprint, TSTInfo.serialNumber,
TSTInfo.genTime, the signingTime attribute, the messageDigest attribute and
the signature. Both are 5453 octets.

  FIELDS THE TWO FIGURES SHOW AND THE TOKEN DOES NOT HAVE: both figures draw a
  `nonce` crossing from the signer to the TSA (source lines 186 and 213), and

  echo one. Measured, not inferred: TimeStampReq is
  SEQUENCE { INTEGER 1, MessageImprint, BOOLEAN TRUE } in both appendices --
  version, messageImprint, certReq -- and TSTInfo has no nonce component.
