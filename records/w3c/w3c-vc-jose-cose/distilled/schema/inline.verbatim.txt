Convention. A region is the .txt lines between its BEGIN and END marker
lines, markers excluded, inclusive line range as given, each line byte for
byte. The rendering (bin/render-w3c) decodes character references, drops
<script> and <style>, puts each HTML block element on one line with its
whitespace collapsed, and opens each table cell with " | ". So the leading
"| " and the inner " | " of a template row are the rendering's, not the
source's: the source is an HTML <table> of two-column rows. A <p> or
<li> inside a cell starts a new line. The five "Additional information"
lines of each template are the five <li> of an <ol type="1">: a browser
numbers them 1 to 5, and the numbers are not text, so neither the source
text nor this copy carries them. Every region cell, with the cell markers
removed, was found in the HTML of its own display, markup removed. Each
region's sha256 (its lines joined by a line feed, no trailing line feed)
and the HTML line range of its display are in README.md.

==== I-11  section 1.1.2.2  the SD-JWT format, a four-item list
     heading line 150: 1.1.2.2.  SD-JWT Format and Requirements
     .txt lines 153-156; HTML (.bin) lines 1327-1344
---- BEGIN VERBATIM I-11 ----
An SD-JWT consists of three main parts: the SD-JWT itself, optional disclosures, and an optional KB-JWT (Key Binding JWT). These parts are separated by tilde (~) characters.
If the KB-JWT is not present, the SD-JWT must end with a tilde (~) character. This is crucial for correct parsing and processing of the SD-JWT.
Selective disclosure is achieved through the use of disclosure objects. These are base64url-encoded JSON arrays containing the digest of the disclosed claim, the claim name, and the claim value.
Each disclosable claim is combined with a salt value before hashing to prevent dictionary attacks.
---- END VERBATIM I-11 ----
