# Distilled artifacts — OWASP DevSecOps Maturity Model (DSOMM)

FX-1 extraction (library#69, family 4). The source of record is the YAML data
model `generated/model.yaml` at tag v5.1.0 (`content.sha256` in `record.yaml`);
every artifact cites that file by line number, read through the FX-1 YAML
profile (sections are key paths; only prose values are quoted, never keys).
Coverage figures live once, in `record.yaml` `distillation.artifacts`, so they
are not restated here.

| artifact | what it is |
|---|---|
| `requirements.yaml` | **machine source.** One entry per activity under its source uuid (`owasp-dsomm#<uuid>`), text = the activity's measure, with level, dependsOn, difficulty, usefulness, tags; then `#R-NNNN`: the skeleton's sentences (those inside a measure are split_of their activity), pass 1's split children, promoted candidates and hunted texts, the inferred entries (`kind: inferred`), and the verify pass's hunted texts at the end. |
| `inferred-candidates.yaml` | every keyword-less sentence that might bind, and every verbal form in informative text, each with a verdict. |
| `normative.md` | by dimension, sub-dimension and activity: the measure, the assessment lines and the binding sentences, quoted by line marker, descriptive entries by id; the inferred entries; the source defects found; reading notes on the YAML profile. |
| `messages.yaml`, `schema/` | the model's 7 structures and 5 JSON Schemas, all generated by `schema/build.derived.py` from the file itself (no published schema binds model.yaml, see `schema/README.md`); `schema/check.derived.py` validates all 251 activities of the pinned source. |
| `protocol.yaml`, `protocol.md` | the 14 exchanges between parties that activity texts state (approvals, agent delegation, push gates, containment, triage and others), with a Mermaid diagram per flow. DSOMM defines no wire protocol. |
| `state-machine.yaml` | the lifecycles the model implies, stated vs inferred per state and transition. |
| `examples/` | the source's 3 fenced code examples, verbatim (`ex-NN.verbatim.*`, cut and re-checked by script), and our own schema test cases (`*.derived.json`). |
| `design-notes.md` | adopt / adapt / reject against tmodel's and mofn's decisions, and open questions. |
| `skeleton-report.txt` | `bin/fx1-skeleton`'s counts, regenerable. |
| `object-model.yaml`, `object-model.md`, `crosswalk.yaml`, `verification.md` | the earlier secondary-reference pass (2026-10-02/03), kept unchanged: object model, the published samm2 / ISO 27001 / OpenCRE cross-references, and that pass's verification. Only `bin/_yaml.py` reads `crosswalk.yaml` whole (`bin/_record_yaml.py` reads 9 of its 2585 leaves). |

**Source placeholders.** A few source fields hold a literal placeholder token
instead of content. The FX-1 artifacts describe them and do not quote the token
itself (see normative.md; candidate C-0326 quotes a misspelling of it); the earlier pass's `crosswalk.yaml` (lines 9 and 1738) and
`verification.md` (line 35) do carry the token, as that pass's verbatim output.

**Keywords.** `keyword_vocabulary: directives` (lowercase verbal forms). DSOMM
has no requirement level of its own; a measure is a recommended practice. The
reconciliation in `requirements.yaml` accounts for every form.

Nothing here is reviewed by a person yet: `reviewed_by` is empty on every
artifact.
